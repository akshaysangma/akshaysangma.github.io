Environment Setup — Windows

Two practice environments for this course. Set up both; reach for whichever each lesson needs. Reusable reference — every lesson links here.

Platform: Windows 10/11 Path A: Databricks Free Edition Path B: Local Python ~20 min total
Recommended order Do Path A first — it's zero-install and runs Spark in the cloud, so you can start Lesson 1 in five minutes with nothing to break. Then set up Path B (local Python) in the background for the pandas/NumPy track and for running PySpark offline.

Path A — Databricks Free Edition (cloud, zero install)

In 2025 Databricks retired Community Edition and replaced it with Free Edition — a fuller, no-cost workspace with serverless compute, so you never create or configure a cluster yourself.¹ No credit card required. This is the closest thing to a real on-the-job Databricks environment you can get for free, which matters for a career switch.

  1. Go to databricks.com/learn/free-edition (or directly signup.databricks.com).
  2. Choose Free Edition (not the 14-day paid trial). Sign up with email / Google / Microsoft.
  3. Verify your email; the workspace is provisioned automatically — nothing to install.
  4. Inside the workspace: + New → Notebook. Set the language to Python. A serverless compute attaches on its own.
  5. Test it — type and run (Shift+Enter): 
    print(spark.version)
spark.range(5).show()
    In Databricks notebooks the spark session already exists — you never call SparkSession.builder there.
Watch out Free Edition has daily compute/storage limits and is non-commercial (learning only) — fine for this course. Don't confuse it with the paid free trial, which expires in 14 days and asks for billing.

Path B — Local Python + PySpark on Windows

For the Python foundation track (NumPy/pandas) and for running PySpark offline. Three pieces: Python, then a project folder with a virtual environment, then Java (only needed for PySpark).

1. Install Python

  1. Download Python 3.11 or 3.12 from python.org/downloads. (Avoid the very newest release — some data libraries lag a few weeks.)
  2. Run the installer and check "Add python.exe to PATH" on the first screen — this is the #1 missed step on Windows.
  3. Open a fresh PowerShell and verify: 
    python --version
pip --version

2. Create a project folder + virtual environment

A venv keeps this course's packages isolated from the rest of your system — standard professional practice.

# in PowerShell
mkdir data-pipelines-practice
cd data-pipelines-practice
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # prompt now shows (.venv)

# the Python foundation toolkit + Spark + notebooks
pip install numpy pandas pyspark jupyter
If Activate.ps1 is blocked PowerShell may refuse the script with an execution-policy error. Fix it once: 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Then re-run the Activate.ps1 line. Re-activate the venv every new terminal.

3. Install Java (required for PySpark only)

NumPy and pandas need nothing extra. PySpark runs on the JVM, so it needs a JDK. Modern PySpark (4.x) requires Java 17 or later and Python 3.10+.²

  1. Install Eclipse Temurin JDK 17 (free OpenJDK) from adoptium.net — pick the Windows .msi. During install, enable "Set JAVA_HOME variable" if offered.
  2. Confirm in a new PowerShell: 
    java -version          # should show 17.x
echo $env:JAVA_HOME    # should print the JDK path
  3. If JAVA_HOME is empty, set it (Start → "Edit the system environment variables" → Environment Variables → New): JAVA_HOME = C:\Program Files\Eclipse Adoptium\jdk-17..., then reopen the terminal.

4. Verify the whole stack

python -c "import numpy, pandas; print('py data ok', numpy.__version__, pandas.__version__)"
python -c "from pyspark.sql import SparkSession; s=SparkSession.builder.getOrCreate(); print('spark ok', s.version); s.stop()"

The first PySpark run is slow (it starts a JVM) and prints some WARN lines — that's normal, not an error.

Optional: the winutils gotcha Pure DataFrame work in local mode usually runs fine without it. If you later hit HADOOP_HOME and hadoop.home.dir are unset or a winutils.exe error when writing files, download a matching winutils.exe + hadoop.dll, put them in C:\hadoop\bin, and set HADOOP_HOME=C:\hadoop. Cross that bridge only if you reach it.
