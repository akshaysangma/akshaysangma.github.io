OLTP vs OLAP — the map

The single distinction the whole pipelines chapter hangs on: the database that runs the business vs the store that analyzes it.

~11 min Chapter 3 · Data pipelines The orienting map Retrieval practice inside
The win You'll explain why MySQL (OLTP) and a warehouse (OLAP) are tuned in opposite directions, and why that gap is the reason data pipelines exist — to move and reshape data from one world to the other.

Two opposite jobs

OLTP and OLAP optimize for different workloads — that's why you need both.
OLTP (e.g. MySQL)OLAP (warehouse)
WorkloadMany tiny reads/writes ("place this order")Few huge scans ("revenue by region by month")
SchemaNormalized (Lesson 7) for write integrityDenormalized / star schema for read speed
StorageRow-oriented (whole row at once)Column-oriented (one column across all rows)
Sized forLow-latency single-row accessHigh-throughput aggregation
Why columnar wins for analytics "Sum revenue across 50M rows" touches one column. A column store reads just that column's contiguous values (and compresses them well); a row store would drag every column of every row off disk. The opposite is true for "fetch this one order" — that's a row store's home turf.

The pipeline is the bridge

You can't run heavy analytics on the production OLTP database without hurting the app, and you can't serve live traffic from a warehouse. So a data pipeline extracts from OLTP, reshapes, and loads into OLAP. The next lessons are the how: ETL vs ELT, batch vs streaming, warehouse modeling, and CDC.

Your sibling course, Data Pipelines (Spark + Databricks), is the hands-on implementation of this same bridge. This chapter gives you the database-side vocabulary to reason about it.

Check yourself

An analytics query sums one column across 50M rows. Which storage layout wins?
A. Aggregating one column over millions of rows is exactly what columnar storage is built for — it reads only that column's contiguous, well-compressed values. Row storage (B) and OLTP tuning (D) optimize for the opposite: fetching whole individual rows.
Which description fits an OLTP system?
A. OLTP = Online Transaction Processing: lots of small, low-latency reads and writes against a normalized schema (the live app database). B, C, and D all describe the OLAP / analytics side.
Primary source: _Designing Data-Intensive Applications_ — Kleppmann, chapter 3 ("Transaction processing or analytics?").
