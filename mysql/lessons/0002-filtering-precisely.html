Filtering precisely with WHERE

The operators are easy. The one thing that quietly breaks more queries than anything else is NULL — so we make it the centrepiece.

~10 min Chapter 1 · Foundations NULL is the trap Retrieval practice inside
The win You'll filter with =, IN, BETWEEN, and LIKE confidently — and, more importantly, you'll explain SQL's three-valued logic and never again write = NULL or get burned by NOT IN with a NULL in the list.

Precedence bug WHERE country = 'US' OR country = 'UK' AND active = 1 does not mean what it looks like: AND binds first, so it reads as US OR (UK AND active). Always parenthesise mixed AND/OR: (country = 'US' OR country = 'UK') AND active = 1.

The big one: NULL and three-valued logic

NULL means "unknown", not zero and not empty string. Because the value is unknown, any comparison to it is also unknown. SQL logic therefore has three truth values: TRUE, FALSE, and UNKNOWN — and WHERE keeps a row only when its predicate is exactly TRUE. 

WHERE bonus = NULL      -- UNKNOWN for every row → returns nothing, ever
WHERE bonus IS NULL     -- correct: rows where bonus is unknown
WHERE bonus IS NOT NULL -- correct: rows where bonus has a value
Trap — NOT IN with a NULL region NOT IN ('US','UK', NULL) returns zero rows. Internally it becomes region<>'US' AND region<>'UK' AND region<>NULL, and that last term is UNKNOWN, which poisons the whole AND to never-true. IN with a NULL is usually harmless; NOT IN with a NULL is a silent result-killer. Filter the NULLs out first.

Check yourself

Commit before revealing.

Why does WHERE bonus = NULL return zero rows every time?
A. NULL is "unknown", so bonus = NULL evaluates to UNKNOWN for every row, and WHERE only keeps rows that are TRUE. Use IS NULL / IS NOT NULL to test for it. (It's not an error — that's what makes it sneaky.)
region NOT IN ('US','UK', NULL) returns no rows. Why?
A. NOT IN (…) expands to a chain of <> joined by AND. region <> NULL is UNKNOWN, and anything AND UNKNOWN can never be TRUE — so no row survives. Strip NULLs from the list before using NOT IN.
