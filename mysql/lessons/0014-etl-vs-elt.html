ETL vs ELT

Same three letters, different order — and the order decides where the transformation work happens and what you can recover later.

~10 min Chapter 3 · Data pipelines Interview favourite Retrieval practice inside
The win You'll state the one structural difference between ETL and ELT, explain why cheap cloud-warehouse compute made ELT the modern default, and name the cases where ETL still wins.

The only difference is when you transform

Extract, Transform, Load — reordered.
ETLELT
OrderExtract → Transform → LoadExtract → Load → Transform
Transform runsIn a separate engine, before landingInside the warehouse, after landing raw
What landsOnly clean, modeled dataRaw data first, then derived tables
Re-process historyHard — raw was discardedEasy — raw is still there
Why ELT became the default Cloud warehouses (Snowflake, BigQuery) and lakehouses made warehouse compute cheap and elastic, so it's now efficient to dump raw data in and transform it in place with SQL (this is what dbt orchestrates). Keeping the raw layer means you can re-derive everything when requirements change — the medallion bronze→silver→gold pattern in your sibling course.
When ETL still wins Transform-before-load is right when raw data must not land as-is: masking/removing PII for compliance, enforcing a strict schema before storage, or when the target has limited compute. "ELT everywhere" is a smell if it means raw regulated data sitting unprotected.

What defines ELT, versus ETL?
A. ELT loads raw data into the warehouse first, then transforms it there with SQL. B describes classic ETL. The raw-first order is what makes re-processing history easy and powers the medallion architecture.
When is ETL (transform before load) still the better choice?
A. If regulated data can't land in raw form, you must transform (mask/drop PII) before loading — classic ETL. B, C, and D are all arguments for ELT (cheap compute, keep raw, SQL-based transforms).
