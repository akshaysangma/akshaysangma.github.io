Orchestration, idempotency & data quality

The three things that separate a script that "works once" from a pipeline you can trust in production — and the finish line of the course.

~13 min Chapter 3 · Data pipelines Production reliability Course capstone
The win You'll explain what an orchestrator's DAG buys you, why every task must be idempotent, and how data-quality checks stop bad data from spreading — then review the whole course with interleaved recall.

Orchestration: dependencies, scheduling, retries

A real pipeline is many tasks with an order ("load dims before facts"). An orchestrator (Airflow, Dagster, Databricks Jobs) models this as a DAG — a directed acyclic graph of tasks and their dependencies. It handles scheduling, runs independent tasks in parallel, retries failures, and alerts on them. The DAG expresses what depends on what, not how each task computes.

Idempotency: safe to run again

The reliability cornerstone Tasks fail and get retried; backfills re-run yesterday. A task is idempotent if running it twice leaves the same result as running it once. Achieve it by replacing, not appending: overwrite the target partition, or UPSERT/MERGE on a key — never blind INSERT, which double-counts on retry. (This is also how you get effectively-once from at-least-once streaming, Lesson 15.)

Data quality: catch bad data early

Bad data caught at ingestion is cheap; bad data in an executive dashboard is expensive. Add automated checks as pipeline gates — fail or quarantine on violation:

  • Schema — expected columns and types are present.
  • Not-null / uniqueness — keys aren't missing or duplicated.
  • Freshness — the latest data is recent enough.
  • Row-count / range — volumes and values are within sane bounds.

Check yourself

Why must a pipeline task be idempotent?
A. Retries and backfills mean tasks will run more than once. Idempotency (overwrite / MERGE on a key) guarantees the second run doesn't double-count or corrupt — it's about correctness under retry, not speed.
What does an orchestrator's DAG primarily express?
A. A DAG encodes which tasks depend on which (the run order), letting the orchestrator parallelize independents, retry failures, and schedule the whole thing. The query plan (B) is the database's job — Lesson 11.
