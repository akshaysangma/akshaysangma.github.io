MySQL & Data Pipelines Glossary

The canonical language for this course. Every lesson uses these exact terms; definitions are tight and opinionated.

How to use it This is the compressed essence of the course — the fastest revision before an interview. When several words mean the same thing, we pick one and list the rest as aliases to avoid.

Query processing

Logical processing order
The fixed sequence the SQL standard says a query means: FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. Distinct from the physical plan the optimizer actually runs.
Avoid: execution order, run order (say "logical" or "physical").
Predicate
A condition evaluating to true / false / unknown, used to keep or drop rows or groups.
Avoid: filter expression, criteria.
Row filter vs group filter
A row filter (WHERE) discards rows before grouping; a group filter (HAVING) discards whole groups after. "WHERE filters rows, HAVING filters groups."
Aggregate (function)
A function collapsing many rows into one value — COUNT, SUM, AVG, MIN, MAX. Meaningful only after grouping, so it can't sit in WHERE.
Alias
A name given to a column/expression in SELECT via AS. Born at the SELECT step, so visible to ORDER BY but not WHERE (standard SQL).
Three-valued logic
SQL truth has three values — TRUE, FALSE, UNKNOWN — because any comparison to NULL is UNKNOWN. WHERE keeps only TRUE rows.
Anti-join
The pattern for "rows in A with no match in B": LEFT JOIN then WHERE b.key IS NULL.
Avoid: exclusion join, missing join.
Fan-out
Row multiplication when joining a one-to-many relationship — aggregates over the joined result then double-count. Aggregate to the right grain first.
CTE (Common Table Expression)
A named subquery defined with WITH, referenced below for readability and recursion. Not guaranteed to materialise once.
Window function
A function computing a value per row over a related set defined by OVER (PARTITION BY … ORDER BY …), without collapsing rows. ROW_NUMBER is unique; RANK gaps on ties; DENSE_RANK doesn't.

Modeling & internals

Normalization
Designing tables so each fact is stored once, removing redundancy. 1NF (atomic values) → 2NF (whole-key dependence) → 3NF (no transitive dependence). Optimizes writes/integrity.
Avoid: cleaning up the schema.
Denormalization
Deliberately reintroducing redundancy (wide tables, star schema) to make reads fast. The right call for analytics; the wrong default for OLTP.
Update anomaly
A bug caused by redundancy: changing a duplicated fact in one place leaves stale copies elsewhere. (Also insertion and deletion anomalies.)
Primary key
The column-set uniquely identifying a row; NOT NULL + unique. In InnoDB it's the clustered index. Prefer a small surrogate key (generated id) over a natural key (real data).
Foreign key / referential integrity
A constraint that every child value must match an existing parent row — you can't reference or orphan a missing parent. That guarantee is referential integrity.
Junction table
A bridge table holding two foreign keys, one row per pairing — the only way to model many-to-many.
Avoid: link table, mapping table.
Index (B-tree)
A sorted lookup structure giving O(log n) equality, range, prefix, and ordered access on its column(s).
Clustered index
In InnoDB, the primary key — the rows themselves are stored in its B-tree, in PK order. One per table.
Covering index
An index containing every column a query needs, so it's answered from the index alone (Using index in EXPLAIN).
Left-prefix rule
A composite index on (a,b,c) serves predicates starting from the left (a, a,b, a,b,c) — never b or c alone.
Transaction / ACID
A group of statements that commit or roll back together, with guarantees of Atomicity, Consistency, Isolation, Durability.
Isolation level
The dial trading concurrency for correctness: READ UNCOMMITTED → READ COMMITTED → REPEATABLE READ (InnoDB default) → SERIALIZABLE. Each blocks more read anomalies (dirty, non-repeatable, phantom).

Data pipelines

OLTP
Online Transaction Processing — the live app database: many small reads/writes, normalized, row-stored (e.g. MySQL).
OLAP
Online Analytical Processing — the analytics store: few large scans, denormalized, column-stored (a warehouse).
ETL vs ELT
ETL transforms before loading (clean data lands). ELT loads raw first, transforms in the warehouse (re-processable; the modern default).
Batch vs streaming
Batch processes bounded finite datasets on a schedule; streaming processes an unbounded continuous flow with low latency.
Windowing
Slicing an unbounded stream into finite intervals (tumbling/sliding/session) so aggregates can be computed and emitted.
Data warehouse / star schema
A denormalized analytics store. The star schema places a fact table (measurable events) in the center, joined to dimension tables (descriptive context).
Grain
What one fact-table row represents. Choose the most detailed atomic grain — you can roll up, never drill back down.
CDC (Change Data Capture)
Capturing every row change by reading MySQL's binlog (with binlog_format=ROW), rather than polling — low source impact, captures deletes.
Idempotency
A task that, run twice, leaves the same result as once — achieved by overwrite or UPSERT/MERGE, never blind INSERT. The cornerstone of safe retries.
DAG / orchestration
A directed acyclic graph of pipeline tasks and their dependencies; an orchestrator schedules it, parallelizes independents, and retries failures.
