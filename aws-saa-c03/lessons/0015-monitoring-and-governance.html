Monitoring & Governance

CloudWatch, CloudTrail, and Config look interchangeable until a scenario forces you to choose. This lesson gives you the one-line test that separates them — plus CloudFormation, Organizations/SCPs, and Systems Manager.

Lesson 15 ~10–12 min Cross-cutting — Management & Governance Service-distinction drills

The win

By the end of this lesson you'll instantly map a scenario verb to the right service. The exam loves to put CloudWatch, CloudTrail, and AWS Config in the same four options and trust you to confuse them. You won't — because you'll carry one sentence: CloudWatch = how is it doing; CloudTrail = who did what; Config = what changed / is it compliant. Everything else here (CloudFormation, Organizations + SCPs, Systems Manager) is about picking the managed, account-wide tool over the manual one.

The three that get confused — the one-line test

Read the scenario and ask which question it is really asking. That single question picks the service.

Amazon CloudWatch — the performance lens

CloudWatch monitors your resources and applications in real time for performance, operational health and utilisation.Source: What is Amazon CloudWatch? The pieces you must recognise:

  • Metrics — time-series performance data. Many AWS services publish metrics automatically; you can also publish custom metrics from your own applications.
  • Alarms — continuously watch a metric against a threshold; on breach they alert (e.g. SNS) and can trigger automated actions (e.g. Auto Scaling).
  • CloudWatch Logs — central ingestion and storage of logs in log groups/streams. Logs Insights runs fast interactive queries over that data; metric filters turn log patterns into metrics you can alarm on.
  • Dashboards — a single visual view of metrics and logs, shareable across accounts and Regions.
  • EventBridge relationship — CloudWatch handles the metrics/logs side; EventBridge (which grew out of CloudWatch Events) is the event-bus that routes events to targets. If the scenario is "react to an event / route it to a target", that's EventBridge, not a CloudWatch alarm.

AWS CloudTrail — the audit lens

CloudTrail records actions taken by a user, role, or AWS service as events — across the console, CLI, SDKs and APIs — so you can answer who or what took which action, on which resource, and when.Source: What is AWS CloudTrail? Exam-critical specifics:

  • Management events vs data events. Management events are control-plane operations (e.g. AttachRolePolicy, CreateSubnet, CreateTrail, plus non-API events like ConsoleLogin). Data events are high-volume data-plane operations (S3 GetObject/PutObject/DeleteObject, Lambda Invoke). By default a trail logs management events but NOT data events — you must opt in to data events.
  • Event history gives you a searchable, immutable record of the past 90 days of management events with no setup. To keep events longer, create a trail that delivers to S3 (optionally to CloudWatch Logs / EventBridge).
  • Multi-Region trail — a single trail can capture events from all Regions; an organization trail captures across all accounts in AWS Organizations.
  • Log file integrity validation — CloudTrail can produce hash-and-sign digest files so you can prove log files weren't altered or deleted after delivery. Choose this when the scenario stresses tamper-evident audit logs.

AWS Config — the configuration & compliance lens

AWS Config records the configuration of your resources and how it changed over time, and evaluates resources against rules.Source: What is AWS Config? What to recognise:

  • Configuration history & relationships — "what did this security group look like last Tuesday, and what's related to it?"
  • Config rules continuously evaluate resources as they're created/changed/deleted and flag noncompliant ones; conformance packs bundle rules, and remediation can auto-fix.
  • Aggregators centralise configuration & compliance across multiple accounts and Regions.
The distinction that wins points "Who deleted the bucket?" → CloudTrail. "Is CPU too high / collect the logs?" → CloudWatch. "Has this resource drifted out of compliance, and what was its prior config?" → AWS Config. Three different questions, three different services — never the same one.
Classic trap CloudWatch and CloudTrail both deal in "logs", so the exam offers CloudWatch when the real question is an audit ("who made this API call"). CloudWatch tells you a metric spiked; only CloudTrail tells you the identity and action behind it. If the verb is who / deleted / changed-by-whom / unauthorized API call, reach for CloudTrail.

The governance toolkit — managed and account-wide

AWS CloudFormation — infrastructure as code

You write a template describing the resources you want; CloudFormation provisions and configures them as a stack, handling dependencies, and deletes them as a unit.Source: What is CloudFormation? Reuse one template to replicate infrastructure consistently across Regions. Drift detection tells you when live resources diverge from the template; StackSets deploy a stack across many accounts and Regions. Scenario cue: "repeatable, version-controlled, automated provisioning" → CloudFormation.

AWS Organizations + Service Control Policies (SCPs)

Organizations groups accounts under one management account, gives you consolidated billing, and lets you organise accounts into OUs.Source: Service control policies (SCPs) SCPs are guardrails: they set the maximum available permissions for IAM users and roles in member accounts. Key exam facts:

  • An SCP never grants permissions — it only sets a ceiling. Effective permissions are the intersection of the SCP and the identity-based policies.
  • SCPs apply to all users and roles in member accounts, including the root user — an account admin with AdministratorAccess still can't exceed the SCP.
  • SCPs do not affect the management account.

Scenario cue: "ensure no account in the org can use a Region/service, even admins" → that's an SCP, not an IAM policy (which you'd have to attach per principal and which an account admin could override).

AWS Systems Manager (SSM)

Operate managed nodes at scale without logging into servers.Source: What is AWS Systems Manager? Three capabilities the exam tests:

  • Session Manager — browser/CLI shell into an instance without SSH keys, bastion hosts, or open inbound ports. The keyless-access answer.
  • Patch Manager — automate patching and report patch compliance across your fleet.
  • Parameter Store — store configuration data and secrets for applications to reference (free tier; encrypts with KMS for SecureString).
Two more to recognise AWS Control Tower sets up and governs a multi-account landing zone with guardrails and Account Factory — it orchestrates Organizations, IAM Identity Center and Service Catalog for you. AWS Trusted Advisor inspects your account and recommends improvements across cost, performance, security, fault tolerance, and service limits. If the scenario says "best-practice checks/recommendations" think Trusted Advisor; "set up a governed multi-account environment fast" think Control Tower.

See it in action

Commit to an answer before revealing each explanation — retrieval is what makes the distinction stick.

Q1. Which service answers the question?
A production S3 bucket was deleted last night. Security needs to know which IAM identity made the DeleteBucket API call, and when.
Question asked: "who did what?" → CloudTrail. CloudTrail records the identity, action, resource and time of API/console activity — exactly the audit question here (note: DeleteBucket is a management event, logged by default). (A) CloudWatch only tells you a metric moved — never who acted; this is the headline trap. (B) Config shows the bucket's past config and that it changed, but not the calling identity. (D) Flow Logs capture network traffic, not API calls. Answer: C.
Q2. Which service answers the question?
An operations team wants to be alerted when an EC2 instance's CPU exceeds 80% and to aggregate the application's logs centrally so they can query them.
Question asked: "how is it doing?" → CloudWatch. Alarms watch a metric against a threshold and notify/act on breach; CloudWatch Logs centralises logs and Logs Insights queries them. (B) CloudTrail audits API activity, not CPU or app logs. (C) Config checks configuration/compliance, not live performance. (D) X-Ray is for distributed tracing of requests, not a CPU threshold alert. Answer: A.
Q3. Which service answers the question?
A compliance team must continuously verify that every EBS volume stays encrypted, be notified when one becomes noncompliant, and review how a resource's configuration changed over time.
Question asked: "is it compliant / what changed?" → AWS Config. Config rules continuously evaluate resources, flag noncompliance, and the configuration history shows change over time. (A) CloudTrail records the API event but doesn't continuously evaluate compliance or keep a config timeline. (B) There's no such encryption "metric"; CloudWatch is performance, not config compliance. (C) Drift detection only compares against a CloudFormation template, not an ongoing compliance rule across all volumes. Answer: D.
Q4. Which option does the procedure select?
A company with many AWS accounts under AWS Organizations must guarantee that no account — not even an account administrator — can use any Region outside eu-west-1.
Priority: an org-wide guardrail admins cannot escape → SCP. An SCP sets the maximum permissions for member accounts and applies to all principals including root and account admins, so no one can exceed it. (A) Per-user IAM policies are easy to miss and an account admin can change them — no hard ceiling. (C) Config only detects noncompliance after the fact; it doesn't prevent the action. (D) Permissions boundaries are per-principal IAM constructs and don't blanket an organization. Answer: B.

The one sentence to remember

Takeaway CloudWatch = how is it doing (metrics/logs/alarms); CloudTrail = who did what (API audit); Config = what changed / is it compliant. For account-wide control prefer the managed, blanket tool: SCPs for guardrails, CloudFormation for repeatable provisioning, Systems Manager Session Manager for keyless access.
