VPC & Network Security

The firewall distinction the exam loves to test, and how to pick the right VPC connectivity option every time. Domain 1 (Security) is your biggest point pool — this is where you defend it.

Lesson 9 ~10 min Security · Domain 1 · 30% Core networking

The win

By the end of this lesson you'll never again confuse a Security Group with a Network ACL — the single most-tested VPC comparison — and you'll have a clean decision tree for VPC connectivity: when to reach for a NAT Gateway, VPC Peering, a Transit Gateway, or a VPC Endpoint. These show up across Domain 1 scenarios, and getting them right is nearly free points once the distinctions click.

The mental model: layers of a VPC

A VPC is your private network in AWS. Inside it you carve subnets, each living in one Availability Zone. Traffic is filtered at two layers, and the exam tests whether you know which layer does what:

  • Network ACL — guards the subnet boundary (the perimeter fence).
  • Security Group — guards the instance / ENI (the lock on each door).

A packet entering a subnet passes the NACL first, then the Security Group on the target instance. Two layers, two very different rule models.

Security Group vs Network ACL

Memorise this table — it is the highest-frequency VPC comparison on the exam.
FeatureSecurity GroupNetwork ACL
LevelInstance (ENI)Subnet
StateStateful — return traffic auto-allowedStateless — must allow return explicitly
RulesAllow onlyAllow and Deny
EvaluationAll rules evaluated togetherNumbered order, first match wins
Exam tell Two phrases decide most questions here. "Return traffic allowed automatically" = Security Group (stateful). "Explicitly block / deny a specific IP" = Network ACL — because only NACLs have Deny rules. A Security Group can never deny; it can only allow, so the absence of an allow rule is its only "block".
Trap Because a Security Group only allows traffic, you cannot use it to block one bad IP while permitting everyone else — there is no "deny" to express. Reach for a NACL with a numbered Deny rule for that. Watch for answers that try to "deny an IP with a Security Group"; they are always wrong.

Stateful vs stateless, concretely

Stateful means the firewall remembers outbound flows: if your instance's Security Group allows an outbound request, the response is allowed back in automatically — you don't write a return rule. A NACL has no memory: if you allow inbound traffic on port 443, you must also allow the outbound ephemeral-port range (1024–65535) for the reply, or it's dropped. This asymmetry is a favourite exam wrinkle.

Public vs private subnets, IGW, and NAT

A subnet is public when its route table sends 0.0.0.0/0 to an Internet Gateway (IGW) and the instances have public IPs. It's private when it has no such route — instances there cannot be reached from the internet, and cannot reach out either, until you add a path.

To give private instances outbound-only internet access (e.g. to download patches) without exposing them to inbound connections, you route their 0.0.0.0/0 to a NAT Gateway sitting in a public subnet.

NAT Gateway vs NAT Instance.
NAT GatewayNAT Instance
ManagementManaged by AWS, no patchingSelf-managed EC2, you patch/scale it
AvailabilityHighly available within its AZ (deploy one per AZ for full HA)Single instance = single point of failure
ThroughputScales automatically, up to 100 GbpsLimited by instance type
ExtrasNone — outbound NAT onlyCan do port-forwarding / act as a bastion (legacy)
Heuristic "Managed, highly available outbound internet for private subnets" → NAT Gateway, one per AZ. NAT Instance is the legacy, self-managed answer — usually a distractor unless the question explicitly wants port-forwarding or the cheapest possible option for tiny traffic.

Connecting VPCs and on-prem

OptionUse when / key fact
VPC Peering1:1 private link between two VPCs. NOT transitive: A–B and B–C does not give you A–C. Fine for a handful of VPCs; becomes a tangle at scale.
Transit GatewayHub-and-spoke, transitive. One central router connecting many VPCs and on-prem. "3+ VPCs (and/or on-prem) all need to talk" → Transit Gateway.
Trap VPC Peering is not transitive. With many VPCs you'd need a full mesh — N×(N−1)/2 peerings — which is the wrong answer when a question describes three or more VPCs (plus maybe on-prem) all needing to reach each other. That's the Transit Gateway scenario.

Reaching AWS services privately: VPC Endpoints

Private instances often need to talk to AWS services like S3 — but routing that through a NAT Gateway sends it over the public internet and costs NAT data charges. VPC Endpoints keep that traffic inside the AWS network instead.

Gateway EndpointInterface Endpoint (PrivateLink)
How it worksRoute-table entry to the serviceAn ENI with a private IP in your subnet
CostFreeHourly charge + data processing
SupportsS3 and DynamoDB onlyAlmost everything else (SQS, SNS, EC2 API, Kinesis…)
Exam tell "Private subnet needs S3/DynamoDB access without a NAT Gateway or internet" → Gateway Endpoint (it's free, and those two services are the only ones it serves). Any other service privately → Interface Endpoint / PrivateLink.

Seeing the traffic: VPC Flow Logs

VPC Flow Logs capture metadata about IP traffic — including whether each flow was accepted or rejected — and ship it to CloudWatch Logs, S3, or Kinesis Data Firehose. When a question is about troubleshooting connectivity ("why is traffic being dropped?") or security forensics ("which IPs hit this ENI?"), Flow Logs is the tool. They record metadata, not packet contents.

See it in action

Commit to an answer before revealing the explanation — retrieval is what makes it stick.

Q1. Which option meets the requirement?
A security team has identified a malicious IP range and must explicitly block all traffic from that range at the subnet boundary, while continuing to allow all other inbound traffic to the web servers.
Priority: explicit DENY at the subnet level → Network ACL. Only NACLs support Deny rules, and they operate at the subnet boundary — exactly what's asked. (A) and (D) are traps: Security Groups have no deny rules, they only allow. (C) doesn't work either, because Security Groups allow all sources unless restricted; there's no per-IP "remove" that blocks one range while permitting the rest. Answer: B.
Q2. Which option meets the requirement?
Instances in a private subnet need to read and write objects in Amazon S3. The company wants this access to be private (not over the internet), with no NAT Gateway and no Internet Gateway, and at the lowest cost.
Priority: private S3 access, no NAT/IGW, lowest cost → Gateway Endpoint. S3 (and DynamoDB) are served by free Gateway Endpoints via a route-table entry — exactly this scenario. (A) and (D) violate "no NAT/IGW" and send traffic over the internet. (B) would technically reach S3 but an Interface Endpoint costs hourly + data charges, so it loses on cost when a free Gateway Endpoint exists. Answer: C.
Q3. Which option meets the requirement?
An organisation has four VPCs plus an on-premises data center that all need to communicate with each other. They want a scalable design with the least ongoing management overhead as more VPCs are added.
Priority: many networks (3+) all need to talk, scalably → Transit Gateway. A TGW is a transitive hub-and-spoke router that connects many VPCs and on-prem in one place, scaling cleanly as VPCs are added. (A) is a mesh that grows as N×(N−1)/2 — operational sprawl. (B) fails because VPC Peering is not transitive: the central VPC cannot forward traffic between two peers. (C) connects to on-prem but not the VPCs to each other. Answer: D.
Q4. Which statement explains the behaviour?
An engineer adds only an inbound allow rule on port 443 to an instance's Security Group and adds no outbound rules. HTTPS responses still flow back to clients correctly. Why?
Security Groups are stateful. Once inbound traffic is allowed, the response is permitted back out automatically — no outbound rule needed. (B) describes a NACL, which is stateless and would require an explicit return rule. (C) is wrong: NACLs and SGs are independent layers, and the default NACL allows all traffic anyway. (D) invents a non-existent rule — ports are not "always allowed." Answer: A.

The one paragraph to remember

Takeaway Security Group = instance level, stateful, allow-only. NACL = subnet level, stateless, allow and deny in numbered order — the only place you can block an IP. NAT Gateway = managed, HA outbound internet for private subnets. Peering = 1:1, not transitive; Transit Gateway = transitive hub for many VPCs + on-prem. Gateway Endpoint = free, S3/DynamoDB only; Interface Endpoint/PrivateLink = paid ENI for everything else. Flow Logs = see accepted/rejected traffic.
Primary source to read next (15 min): the VPC Network ACLs guide (SG vs NACL). Focus on the stateful/stateless distinction and the numbered-rule evaluation order — that's where the exam's wrinkles live.
