Hybrid Connectivity & API Gateway

Connect on-prem to AWS with the right link, then front your APIs and back up your data with the right managed service. Four high-frequency "which service?" decisions in one lesson.

Lesson 11 ~11 min D1 Security · D2 Reliability · D3 Performance Hybrid & integration

The win

By the end of this lesson you'll reliably pick the right hybrid link (Direct Connect vs Site-to-Site VPN vs Client VPN, and when to combine DX+VPN), and the right managed service to put in front of an API (API Gateway), to centralize backups (AWS Backup), and to migrate a database (DMS). These are bread-and-butter scenario questions — the trap is almost always a service that technically works but isn't what the priority word asked for.

1 · Hybrid connectivity — get on-prem talking to AWS

Three connectivity products solve three different problems. The exam decides between them with one phrase. Direct Connect and Site-to-Site VPN connect networks; Client VPN connects individual remote users.

The combo answer Need a private path AND encryption? Run a Site-to-Site VPN over Direct Connect (DX + VPN) — DX gives the dedicated, consistent path; the VPN adds the IPsec encryption DX lacks. When a question stresses both "private/consistent" and "encrypted in transit", that's the intended answer.
Trap "We need a connection up this week" rules out Direct Connect — provisioning a DX circuit takes weeks. Reach for Site-to-Site VPN, and frequently a VPN is also the cost-effective backup for a primary DX link.

2 · API Gateway — a managed front door for your APIs

Amazon API Gateway is, in AWS's own words, the "front door" for applications to reach backend logic — "a fully managed service … to create, publish, maintain, monitor, and secure APIs at any scale." Together with Lambda it forms the app-facing part of AWS's serverless stack. It supports three API types: REST, HTTP, and WebSocket.Source: What is Amazon API Gateway?

What it does for you, so your backend doesn't have to:

  • Throttling / rate limiting — absorbs and shapes traffic spikes; REST APIs add per-client rate limiting via API keys and usage plans.
  • Caching — REST APIs can cache responses to cut latency and backend load (HTTP APIs do not offer caching).
  • Authorization — IAM policies, Amazon Cognito user pools, and Lambda authorizers (custom auth). REST also supports resource policies; HTTP APIs add native JWT authorizers. (Mutual TLS is available on both REST and HTTP APIs.)
  • Integrations — Lambda functions, HTTP endpoints, other AWS services, and private integrations to NLB/ALB. WAF and X-Ray integrate with REST APIs.
REST API vs HTTP API — the exam's API Gateway sub-decision. Verified against the AWS "Choose between REST APIs and HTTP APIs" doc.

Exam tell "Expose a Lambda backend as an API" → API Gateway. If the scenario needs API keys, caching, request validation, or WAF → REST API. If it just wants the cheapest, lowest-latency proxy to Lambda/HTTP with simple auth → HTTP API.

3 · AWS Backup — one policy, every backup

AWS Backup is a fully managed, centralized, policy-based service that automates data protection across AWS services from one console — so you stop writing per-service backup scripts.Source: What is AWS Backup? Two core building blocks:

  • Backup plans — policies defining schedule, retention, and lifecycle (warm → cold tier). Assign resources by tag.
  • Backup vaults — encrypted, access-controlled stores for recovery points; Vault Lock enforces a write-once-read-many (WORM) model.

It backs up a broad set of resources from one place, including Amazon EBS, EFS, RDS & Aurora, DynamoDB, EC2, the FSx family, Storage Gateway, DocumentDB, Neptune, Redshift, S3, and more — with cross-Region and cross-account copy for DR and compliance.

Exam tell "Centralize / automate / single policy for backups across multiple services (EBS + RDS + DynamoDB + EFS…)" → AWS Backup. If a question instead names a single service's native mechanism (e.g. an RDS automated snapshot for just one DB), you don't necessarily need AWS Backup — the centralization across services is the signal.

4 · DMS — migrate databases with minimal downtime

AWS Database Migration Service migrates relational databases, data warehouses, and NoSQL stores into AWS or between cloud/on-prem combinations. Crucially, the source stays operational during the migration: DMS can replicate ongoing changes (CDC) to keep source and target in sync, enabling near-zero-downtime cutover.Source: What is AWS DMS?

Migration typeMeaningTooling
HomogeneousSame engine (Oracle → Oracle, MySQL → Aurora MySQL)DMS alone — schemas are compatible
HeterogeneousDifferent engine (Oracle → Aurora PostgreSQL, SQL Server → MySQL)DMS + Schema Conversion (AWS SCT / DMS Schema Conversion) to convert schema & code first, then DMS moves the data
Exam tell "Migrate a database with minimal/near-zero downtime" → DMS (source keeps running, CDC syncs changes). If the engines differ, add the Schema Conversion Tool (SCT).

See it in action

Run the Lesson-1 procedure on each: find the priority word, eliminate what doesn't fit, then pick the best survivor. Commit before revealing.

Q1. Which option does the procedure select?
A financial firm runs a latency-sensitive trading workload that must reach AWS over a consistent, high-bandwidth, dedicated connection — internet jitter is unacceptable. They accept a multi-week provisioning lead time. Which link?
Priority words: "consistent, high-bandwidth, dedicated" → Direct Connect. Only a dedicated private circuit gives predictable latency independent of the internet. (A) is the classic trap — a VPN is encrypted and fast to deploy but rides the variable public internet. (B) Client VPN is for individual remote users, not a site link. (D) NAT is outbound internet for private subnets, unrelated. Answer: C.
Q2. Which option does the procedure select?
A company has a Direct Connect link to AWS but a compliance rule now requires all traffic in transit to be encrypted, while keeping the private, consistent path. What should they do?
Priority: "encrypted in transit" AND "keep the private, consistent path". DX is not encrypted by default; layering IPsec VPN over it adds encryption while preserving the dedicated path — the standard DX + VPN pattern (B). (A) throws away the consistent private path. (C) gateway endpoints are for S3/DynamoDB access within a VPC, not on-prem transit encryption. (D) CloudFront is edge caching for HTTP, irrelevant here. Answer: B.
Q3. Which option does the procedure select?
A team wants to expose a Lambda backend as a public REST API that throttles each client with API keys, caches responses, and authenticates callers — with the least servers to manage. What should they use?
Priority: managed front door with API keys + caching + auth. API Gateway is the managed "front door" for APIs and integrates natively with Lambda. The specific needs — API keys / per-client throttling and response caching — are REST-API features, so (A). (D) HTTP API is cheaper but offers neither API keys nor caching, so it fails the requirement. (B) ALB can invoke Lambda but lacks API keys/usage plans/caching. (C) self-managed EC2 is the high-overhead distractor. Answer: A.
Q4. Which option does the procedure select?
An operations team must centralize and automate backups across EBS volumes, RDS databases, DynamoDB tables, and EFS file systems under a single retention policy, with the least operational effort. What should they implement?
Priority: "centralize + automate + single policy across multiple services" → AWS Backup. It applies one policy-based backup plan across EBS, RDS, DynamoDB, EFS and more, assigned by tag, from a single console (D). (A) custom Lambda scripting is exactly the per-service toil AWS Backup removes — more overhead. (B) is manual and uncentralized. (C) DMS is for database migration/replication, not policy-based backup. Answer: D.

The one sentence to remember

Takeaway Dedicated + consistent → Direct Connect; encrypted + quick → Site-to-Site VPN; both → DX + VPN; remote users → Client VPN. Managed API front door (keys/caching/auth) → API Gateway (REST when you need keys & caching). Centralized cross-service backups → AWS Backup. Near-zero-downtime DB migration → DMS (+ SCT when engines differ).
