Amazon S3: Storage Classes & Features

Pick the right S3 class for any access, retrieval, or durability requirement — and recognize the features the exam loves to test. The highest-yield trap on SAA-C03 lives here: retrieval time.

Lesson 2 ~10 min Domains 3 & 4 · Performance & Cost S3 Storage

The win

By the end of this lesson you'll be able to read an S3 scenario, find the access pattern and the retrieval-time requirement, and land on the one storage class that's both cheap enough and fast enough. You'll also recognize the dozen features (versioning, replication, Object Lock, the encryption family) the exam turns into one-line "which feature does this?" questions.

Two dials decide every S3 class question

All eight classes share the same 11 nines (99.999999999%) durability. So durability is almost never the deciding factor. What changes is:

  1. Retrieval time — milliseconds vs. minutes vs. hours. This is the most-tested column, and the classic trap (see Q1).
  2. AZ count — most classes span ≥3 AZs; One Zone-IA and S3 Express One Zone live in a single AZ (cheaper, but the data is gone if that AZ is lost).

Cost, minimum-duration charges, and the 128 KB minimum billable size are the tie-breakers on top of those two dials.

The #1 S3 trap "Cheapest" is necessary but not sufficient — always check the retrieval time against the scenario's access need. Deep Archive is cheapest but retrieves in hours. If the scenario says "within minutes", you need Glacier Flexible Retrieval (or Glacier Instant if it says milliseconds). Reaching for Deep Archive because it's cheapest is exactly the wrong move AWS is testing.

The Glacier retrieval-speed ladder (memorize it)

Restore options. The cheaper the tier, the slower (and freer) the bulk option.
ClassExpeditedStandardBulk
Glacier Flexible Retrieval1–5 min3–5 hr5–12 hr (free)

Note Deep Archive has no Expedited option — its fastest restore is ~12 hours. So any "fastest possible from the cheapest archive class" question is really asking for Glacier Flexible's Expedited (1–5 min), not Deep Archive.

Billing gotchas Standard-IA, One Zone-IA and Glacier Instant Retrieval have a 128 KB minimum billable object size — storing millions of tiny objects in them can cost more than Standard. (Glacier Flexible Retrieval and Deep Archive have no 128 KB minimum but add ~40 KB of metadata per object instead.) These classes also carry minimum-duration charges (IA = 30 days, Glacier Instant/Flexible = 90 days, Deep Archive = 180 days): delete or transition early and you still pay for the full period.

Practice: choosing the class

Find the access pattern, then the retrieval-time requirement, then the cheapest class that satisfies both. Commit to an answer before you reveal the explanation.

Q1. Which storage class fits?
A media company archives raw footage it accesses only a few times a year. When an editor does request a clip, they need it back within a few minutes. They want the lowest possible storage cost that still meets that retrieval requirement.
Two dials: rare access + "within minutes" retrieval. Deep Archive (A) is cheapest but its fastest restore is ~12 hours — it fails "within minutes", the exact trap. Glacier Flexible Retrieval (B) supports Expedited restore in 1–5 minutes and is far cheaper than IA or Instant — best fit. Standard-IA (C) meets the time easily but costs much more than a Glacier class for once-a-year access. Glacier Instant (D) gives millisecond access but is priced higher than Flexible; you're paying for instant access the scenario doesn't need. Answer: B.
Q2. Which storage class fits?
A data pipeline writes derived thumbnail images that can be regenerated from the originals at any time. They're accessed infrequently. The team wants the lowest cost and is fine losing them in the rare event of an Availability Zone failure, since they can just rebuild them.
The signal is "re-creatable" + "AZ loss tolerable". That's the textbook case for One Zone-IA (D): same millisecond access as Standard-IA but ~20% cheaper because it lives in a single AZ. Standard-IA (B) and Standard (A) pay for ≥3-AZ resilience the scenario explicitly says it doesn't need. Glacier Flexible (C) adds retrieval latency and a 90-day minimum for data that's read more like IA — and the scenario asks for low cost on infrequent but still readily readable objects, not deep archive. Answer: D.

S3 features the exam tests

One-line "tells" for the features that show up as feature-identification questions.
FeatureOne-line tell
Lifecycle rulesAuto-transition objects to cheaper classes and/or expire them after N days. Transitions follow the cost waterfall.
VersioningKeeps multiple object versions; protects against accidental delete/overwrite. Once enabled it can only be suspended, never fully removed.
MFA DeleteRequires an MFA code to delete a version or change the versioning state. Only the bucket owner (root) can configure it.
Replication (CRR / SRR)Async copy to another bucket. CRR = cross-Region (DR, compliance, latency); SRR = same-Region (log aggregation, prod→test). Both require versioning on source and destination.
Transfer AccelerationRoutes uploads through CloudFront edge locations over the AWS backbone — speeds up long-distance uploads.
Pre-signed URLsTime-limited URL granting temporary GET/PUT using the creator's credentials — share a private object without making it public.
Strong consistencyAll GET/PUT/LIST (including overwrites and deletes) are strongly consistent automatically, at no extra cost.
Object Lock (WORM)Write-once-read-many. Governance mode = override with a special permission; Compliance mode = no one, not even root, can delete until retention expires. Plus Legal Hold. Requires versioning.

Practice: features & compliance

Q3. Which feature meets the requirement?
A financial firm must retain audit records in S3 for exactly seven years. A regulator requires that no one — not an administrator and not even the root user — be able to delete or alter a record before its retention period ends.
"Not even root" is the key phrase — that's Compliance mode. Object Lock Compliance (C) makes objects truly immutable for the retention window: no user, including the account root, can delete or overwrite them. Governance mode (B) lets users with a special permission override the lock, so it fails "not even root". Versioning + MFA Delete (A) deters accidental deletion but a privileged user can still delete. A bucket policy (D) can be edited or replaced by an administrator, so it isn't tamper-proof. Answer: C.
Q4. Which encryption option fits?
A security team stores sensitive objects in S3. They need every object encrypted at rest, but more importantly they must be able to produce an audit trail showing exactly when and by whom each encryption key was used, and they want to control key rotation themselves.
"Audit trail of key usage" + "control rotation" → SSE-KMS. KMS integrates with CloudTrail so every encrypt/decrypt call is logged with who and when, and you control key policies and rotation (A). SSE-S3 (B) gives you encryption but no key-level audit trail or rotation control. SSE-C (C) makes you manage and pass keys yourself with no AWS-side usage log. Client-side encryption (D) works but pushes all key management and auditing onto the team — far more operational overhead than the requirement calls for. Answer: A.

The one sentence to remember

Takeaway Durability is equal across classes — decide on retrieval time first, then AZ count, then cost. Never pick the cheapest archive class if the scenario needs the data back fast.
