Security Services

The rest of Domain 1 — the managed services that protect the edge, detect threats, and handle app identity. Lesson 13 gave you IAM and encryption; this lesson gives you the service you reach for when a scenario says "block", "discover", "scan", or "sign in".

Lesson 14 ~10–12 min Security · Domain 1 · 30% — biggest domain Domain 1

The win

Security is 30% of SAA-C03 — the single biggest point pool. Lesson 13 covered who can do what (IAM) and data protection (KMS, Secrets Manager). This lesson covers the other half of Domain 1: picking the right managed security service for a stated need. By the end you'll sort almost any security-service question into one of five buckets and pick the service that owns that bucket — which collapses most distractors immediately.

The five buckets Read the scenario's verb. Block / filter at the edge → WAF, Shield, Network Firewall, Firewall Manager. Need a TLS certificate → ACM. Detect / discover / scan / audit → GuardDuty, Macie, Inspector, Security Hub, Detective. App users signing in → Cognito (or Directory Service for enterprise AD). Share resources across accounts → RAM.

Protect at the edge

These four services keep malicious traffic away from your application. The exam loves to test WAF vs Shield and WAF vs security groups/NACLs.

AWS WAF — the web application firewall (Layer 7)

AWS WAF lets you "monitor the HTTP and HTTPS requests that are forwarded to your protected web application resources" and control access based on conditions you specify. It attaches a web ACL to one of these resource types:

  • Amazon CloudFront distribution
  • Amazon API Gateway REST API
  • Application Load Balancer
  • AWS AppSync GraphQL API, Amazon Cognito user pool, AWS App Runner, Verified Access, Amplify

WAF rules can match on IP address, country, request headers, string/regex patterns, request length, the presence of SQL injection ("Presence of SQL code that is likely to be malicious"), and cross-site scripting (XSS) ("Presence of a script that is likely to be malicious"). Rules can allow, block, or count requests, and rate-based rules block or count requests that exceed a threshold within a configurable window (1, 2, 5, or 10 minutes). AWS-managed rule groups give you common protections without authoring rules by hand.Source: What is AWS WAF. On the exam, "filter HTTP / block SQLi or XSS / rate-limit a URL on CloudFront, ALB, or API Gateway" → WAF.

Exam trap Security groups and network ACLs operate at Layers 3/4 — IP addresses, ports, protocols. They cannot read the HTTP payload, so they can't detect SQL injection or XSS, and can't rate-limit by URL. Any answer that proposes a security group or NACL to "block malicious HTTP requests" or "stop SQL injection" is wrong. That job belongs to AWS WAF.

AWS Shield — DDoS protection

Both tiers protect against distributed denial-of-service attacks at the network/transport layers (L3/4) and the application layer (L7).

Shield Standard vs Shield Advanced. Standard is automatic and free; Advanced is the paid, "high-risk target" upgrade.

AWS: "Shield Standard is provided automatically and at no extra charge when you use AWS. For higher levels of protection against attacks, you can subscribe to AWS Shield Advanced."Source: How AWS Shield works. If a question asks how to add DDoS protection and the only cost-free, zero-config answer is "you already have it" — that's Standard. If it stresses a high-profile target, the SRT, or reimbursement for attack-driven scaling — that's Advanced.

Network Firewall & Firewall Manager (brief)

  • AWS Network Firewall — a "stateful, managed, network firewall and intrusion detection and prevention service for your VPC." It filters traffic at the VPC perimeter (internet gateway, NAT gateway, VPN/Direct Connect) and supports Suricata-compatible IPS rules and deep packet inspection. Think "managed IDS/IPS firewall for a whole VPC", not "web request filtering" (that's WAF).
  • AWS Firewall Manager — centrally configure and manage WAF rules, Shield Advanced, security groups, Network Firewall, and Route 53 Resolver DNS Firewall across many accounts in AWS Organizations, automatically applying them to new resources. Reach for it when the scenario says "enforce the same protection across all accounts."

Certificates — ACM

AWS Certificate Manager (ACM) creates, stores, and renews public and private SSL/TLS certificates. The two facts the exam tests:

  • Public certificates are free. AWS: "You are not subject to an additional charge for SSL/TLS certificates that you manage with AWS Certificate Manager."
  • Renewal is automatic for ACM-issued certificates, and ACM integrates directly with Elastic Load Balancing, CloudFront, and API Gateway — you attach the certificate, you don't install it on a server.
Two ACM gotchas ACM certs are regional — request one per Region for an ELB. For CloudFront, the certificate must be requested/imported in us-east-1 (N. Virginia). And ACM is not for a standalone web server on a bare EC2 instance — it's for the integrated services above.

Detect & audit

This is the most-confused cluster on the exam. The trick is to anchor each service to what it looks at and what question it answers.

The detection/audit services. Match the data source and the question to the service.
ServiceLooks atAnswers
GuardDutyCloudTrail, VPC Flow Logs, DNS logs (ML + threat intel)"Is something malicious happening in my account right now?" — threat detection
MacieObjects in Amazon S3 (ML + pattern matching)"Where is my sensitive data / PII?" — data discovery & classification
InspectorEC2 instances, ECR container images, Lambda functions"Do my workloads have known software vulnerabilities (CVEs) or network exposure?"
Security HubFindings from GuardDuty, Inspector, Macie + standards checks"What's my overall security posture across accounts?" — aggregation
DetectiveCloudTrail, VPC Flow Logs, GuardDuty findings (graph)"What's the root cause of this finding?" — investigation

The official one-liners worth memorising:

  • GuardDuty — "a threat detection service that continuously monitors, analyzes, and processes AWS data sources and logs… uses threat intelligence feeds… and machine learning (ML) models to identify suspicious and potentially malicious activity."
  • Macie — "a data security service that discovers sensitive data by using machine learning and pattern matching" in S3, including "multiple types of personally identifiable information (PII)."
  • Inspector — "a vulnerability management service that automatically discovers workloads and continually scans them for software vulnerabilities and unintended network exposure" across EC2, ECR, and Lambda.
  • Security Hub — gives "a comprehensive view of your security state", runs checks against standards (FSBP, CIS, PCI DSS, NIST), and "receives findings from other AWS services—such as Amazon GuardDuty, Amazon Inspector, and Amazon Macie." Single pane of glass.
  • Detective — "helps you analyze, investigate, and quickly identify the root cause of security findings" using ML and graph theory; it links changes back to GuardDuty findings.
Exam trap GuardDuty vs Macie is the classic mix-up. GuardDuty detects threats and malicious behaviour from logs. Macie discovers sensitive data (PII) sitting in S3. "Find unencrypted credit-card numbers in our buckets" → Macie. "Detect a compromised instance mining crypto / unusual API calls" → GuardDuty. And GuardDuty detects while Detective investigates — Detective doesn't generate the threat alerts, it explains them.

Identity for applications

Lesson 13's IAM is for your AWS principals. When the scenario is about your application's end users, the answer shifts.

Amazon Cognito — sign-up/sign-in for web & mobile apps

Cognito is "an identity platform for web and mobile apps… a user directory, an authentication server, and an authorization service." Know the two components and what each delivers:

  • User pools — the user directory. "Create a user pool when you want to authenticate and authorize users to your app or API." Handles sign-up, sign-in, MFA, and federation with social (Google, Apple, Facebook) and SAML/OIDC IdPs; issues JWT tokens to your app.
  • Identity pools — the AWS credentials broker. "Set up an identity pool when you want to authorize authenticated or anonymous users to access your AWS resources" — it exchanges a token for temporary AWS credentials via STS so the app can call S3, DynamoDB, etc.

Mnemonic: user pool = who is this user (authentication, directory). Identity pool = what AWS resources may they touch (temporary AWS credentials). They work alone or together.Source: What is Amazon Cognito. "Add user sign-up/sign-in and social login to a mobile app" → Cognito user pools.

AWS Directory Service — managed Microsoft Active Directory

For enterprise/workforce identity and Windows workloads, not consumer apps. AWS Managed Microsoft AD is "powered by an actual Microsoft Windows Server Active Directory, managed by AWS in the AWS Cloud" — use it to domain-join EC2 Windows instances, support AD-aware apps (SharePoint, .NET, RDS for SQL Server), and trust an on-prem AD. (Other options: AD Connector proxies to an existing on-prem AD; Simple AD is a low-cost Samba-based basic directory.)

Cognito vs Directory Service "Sign-in for my SaaS app's customers, with social logins" → Cognito. "Managed Active Directory to domain-join EC2 Windows instances / support AD-aware enterprise apps" → AWS Managed Microsoft AD. AWS's own guidance: develop high-scale SaaS apps → Cognito; need AD/LDAP for cloud apps → Directory Service.

Sharing across accounts — RAM

AWS Resource Access Manager (RAM) "helps you securely share your resources across AWS accounts, within your organization or organizational units (OUs), and with IAM roles and users." Create a resource once (e.g. a VPC subnet, Transit Gateway, Route 53 Resolver rule) and share it instead of duplicating it per account. Unlike a raw resource-based policy, RAM lets you share with an entire org/OU without listing account IDs, and shared resources appear natively in the consumer's console. There's no extra charge for RAM itself.Source: What is AWS RAM. "Share a subnet / centrally-created resource with other accounts in our organization" → RAM.

See it in action

For each one, name the bucket (protect / certificate / detect / identity / share) before reading the options. Commit to an answer before revealing the explanation.

Q1. Which service does the scenario call for?
A public web app sits behind an Application Load Balancer. The security team is seeing SQL-injection attempts and malicious HTTP requests and wants to inspect and block them at Layer 7, with managed rule groups for common exploits.
Bucket: protect at the edge → Layer 7 HTTP filtering → AWS WAF. WAF (C) attaches a web ACL to the ALB and inspects the HTTP payload for SQL injection and XSS, with AWS-managed rule groups. Security groups (A) and NACLs (B) work at Layers 3/4 — they can't read the HTTP request, so they can't detect SQLi (the trap). Shield (D) is for DDoS, not request-level exploit filtering. Answer: C.
Q2. Which service does the scenario call for?
A company must find and classify sensitive PII — names, credit-card numbers — that may be stored across hundreds of Amazon S3 buckets, and be alerted where it lives.
Bucket: detect → "sensitive data / PII in S3" → Macie. Macie (B) uses ML and pattern matching to discover and classify PII in S3 objects. GuardDuty (A) is the trap: it's threat detection from logs (CloudTrail, VPC Flow, DNS), not data classification. Inspector (C) scans EC2/ECR/Lambda for CVEs, not S3 data. Detective (D) investigates existing findings; it doesn't scan S3 for PII. Answer: B.
Q3. Which service does the scenario call for?
A team needs a free, auto-renewing public TLS certificate to enable HTTPS on an Application Load Balancer and a CloudFront distribution, with the least operational overhead.
Bucket: certificate → ACM. ACM (D) issues public TLS certificates at no charge, auto-renews them, and integrates directly with ELB, CloudFront, and API Gateway — least overhead. (A) is manual and not free. Secrets Manager (B) stores secrets, it doesn't issue/renew public certs. KMS (C) manages encryption keys, not TLS certificates. (Reminder: for CloudFront, request the ACM cert in us-east-1.) Answer: D.
Q4. Which service does the scenario call for?
A startup is building a mobile app and needs user sign-up and sign-in, plus the option to let users log in with their Google or Apple accounts. They want a managed user directory, not to build auth themselves.
Bucket: identity for an app → Cognito. Cognito user pools (A) are purpose-built as a managed user directory for web/mobile sign-up/sign-in, with built-in federation to social and SAML/OIDC providers. Directory Service (B) is managed Microsoft AD for enterprise/Windows workloads and EC2 domain join — wrong tool for consumer app users. IAM users (C) are for AWS principals, never per app end-user. IAM Identity Center (D) is for workforce/SSO across AWS accounts, not external app customers. Answer: A.

The one sentence to remember

Takeaway Read the verb: block/filter HTTP → WAF (not security groups/NACLs); DDoS → Shield; free TLS cert → ACM; discover PII in S3 → Macie, detect threats from logs → GuardDuty, scan workloads for CVEs → Inspector, aggregate findings → Security Hub, investigate root cause → Detective; app sign-in → Cognito (enterprise AD → Directory Service); share resources across accounts → RAM.
