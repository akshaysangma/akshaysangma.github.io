EC2 Instances & Pricing

Pick the right instance family for the workload, then the right purchasing option for the budget. The second half is pure Cost Optimization — 20% of the exam, and the questions are very pattern-matchable.

Lesson 4 ~10 min Cost Optimization · D4 · 20% Performance Efficiency · D3 Core compute

The win

By the end of this lesson you'll be able to read a workload description — "steady 3-year baseline", "interruptible batch", "needs flexibility across families", "BYOL licensing" — and name the single cheapest purchasing option that still satisfies the constraints. This is one of the highest-yield pattern matches on the whole exam, because cost questions are formulaic once you know the table.

Step 1 — the five instance families

Instance type names read [family][gen][options].[size], e.g. c7gn.xlarge = Compute optimized, generation 7, Graviton + enhanced networking, xlarge. The first letter is what the exam tests: match the bottleneck to the letter.

The five categories. Memorize the letters — questions describe the bottleneck and expect you to pick the family.
CategoryLettersOptimized forTypical workload
General PurposeT, MBalanced compute/memoryWeb servers, small DBs, dev/test
Compute OptimizedCHigh CPUBatch, media transcode, HPC, gaming
Memory OptimizedR, XLarge in-memory datasetsIn-memory DBs, caches, analytics
Storage OptimizedI, D, HHigh local-disk I/ONoSQL, data warehouse, Elasticsearch
AcceleratedP, G, Inf, TrnGPUs / ML chipsML training/inference, graphics
T-family (burstable) T-family instances earn CPU credits while running below a baseline level, then spend those credits to burst above baseline. Perfect for spiky, low-average workloads (a small web app that's mostly idle). Bad for sustained high CPU — you'll exhaust credits and throttle (or pay for unlimited-mode bursting). Sustained CPU → C-family, not T.

Step 2 — purchasing options

Every option below runs the same instances. They differ only in how much you commit and therefore how big a discount you get. The exam game is: read the constraints, then pick the deepest discount you're still allowed to take.

Discounts are AWS "up to" figures, verified against the EC2 purchasing & Savings Plans docs (Jun 2026).

The two decision pivots 1. Can it be interrupted? Yes → Spot (cheapest). No → keep reading.   2. Is the instance family fixed? Fixed → Standard RI or EC2 Instance Savings Plan (both up to 72%). Might change / want Fargate-Lambda too → Convertible RI or Compute Savings Plan (up to 66% — you trade a little discount for flexibility).
RI vs. Savings Plan — the modern nuance Reserved Instances and Savings Plans give the same headline discounts (72% for the locked options, 66% for the flexible ones). Savings Plans are the newer, simpler model: you commit to a $/hour spend rather than to specific reservations. The Compute Savings Plan is the only commitment option that also covers Fargate and Lambda — that detail is the giveaway in flexibility questions.
Spot trap Spot can vanish on a 2-minute warning. It is never the answer for databases, stateful services, or long-running critical work — no matter how much the question dangles "lowest cost". The tell that permits Spot is explicit: "fault-tolerant", "can tolerate interruption", "stateless", "flexible start/finish". Without those words, Spot is the distractor.

Step 3 — match it: practice

Run the two pivots above. Commit to an answer before revealing the explanation — retrieval is what makes it stick.

Q1. Which purchasing option is cheapest here?
A company runs a steady, always-on production API on a fixed m6i.large fleet. The size and family will not change for the next 3 years. They want the lowest cost and can commit.
Pivot 1: not interruptible (production API) → not Spot. Pivot 2: family fixed → take the locked, deepest commitment. A 3-year Standard RI or an EC2 Instance Savings Plan both reach up to 72% — the best discount available to a steady, fixed workload. (D) Convertible caps at 66%; you'd give up discount for flexibility they explicitly don't need. (A) On-Demand is 0% off. (B) Spot would be terminated under load. Answer: C.
Q2. Which purchasing option is cheapest here?
A data team runs a nightly image-processing batch that is fault-tolerant — if a worker dies mid-job, the job is simply retried elsewhere. The schedule is flexible and the work is stateless. They want the lowest possible compute cost.
Pivot 1: explicitly fault-tolerant, stateless, flexible timing → Spot. This is the textbook Spot profile, and Spot is up to 90% off — the deepest discount on the exam. (A) On-Demand is the trap: it "works" but is far more expensive when the workload openly tolerates interruption. (C) RIs suit always-on, not a nightly burst. (D) Dedicated Hosts are about licensing/isolation, not cheapness. Answer: B.
Q3. Which purchasing option fits best?
An org wants to commit to 1 year of compute spend for a discount, but expects to shift between instance families and Regions over the year and is also moving some services to AWS Fargate and Lambda. They want the discount to apply across all of it.
The giveaway is "across families/Regions and Fargate/Lambda". Only the Compute Savings Plan spans any family, any Region, any OS, and Fargate + Lambda — up to 66% off in exchange for that breadth. (A) Standard RIs lock to a family. (B) EC2 Instance Savings Plan locks to one family + Region (deeper 72% discount, but no flexibility and no Fargate/Lambda). (C) Spot has no commitment and can be interrupted. Answer: D.
Q4. Which purchasing option satisfies the requirement?
A company must run commercial software licensed per physical socket/core, under a bring-your-own-license (BYOL) agreement that requires visibility into the underlying physical host and control over instance placement for compliance.
"Per-socket/core licensing" + "BYOL" + "visibility into the physical host" → Dedicated Hosts. Dedicated Hosts give you a whole physical server with visibility into sockets/cores and control over placement, which is exactly what socket-based BYOL licensing requires. (B) Dedicated Instances are also single-tenant but give you no host visibility, so they don't satisfy per-socket licensing or BYOL host-affinity. (C) and (D) are pricing models, not isolation/licensing controls. Answer: A.

The one sentence to remember

Takeaway Match the bottleneck to the family letter, then run two pivots: interruptible? → Spot; otherwise family fixed? → Standard RI / EC2 Instance Savings Plan (72%); need flexibility or Fargate/Lambda? → Convertible RI / Compute Savings Plan (66%). Licensing/host-visibility → Dedicated Hosts.
