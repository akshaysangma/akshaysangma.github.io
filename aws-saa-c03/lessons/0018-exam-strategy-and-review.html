The five-move test-taking method

This is the Lesson 1 lens, tightened for speed and the clock:

  1. Read the priority word first. Before the options, find the qualifier: cheapest / most cost-effective, most available / fault-tolerant, least operational overhead, highest performance / lowest latency, most secure. That word is the grading rubric for this question.
  2. Eliminate the non-functional. Cross out any option that doesn't actually solve the problem or uses a service for something it can't do. On a 4-option question, killing two distractors turns a 25% guess into a coin flip.
  3. Apply the priority. Among survivors, pick the one that best serves the named priority — cheapest working option for a cost question, the Multi-AZ/multi-Region one for an availability question, the managed/serverless one for "least operational overhead".
  4. Flag-and-return. If you can't decide in ~90 seconds, pick your best guess, flag it, and move on. Never let one hard question eat the time of three easy ones.
  5. Sweep before submit. Use the leftover time to revisit flagged questions, then confirm zero blanks.
Time budget 2 min/question is an average, not a target. Bank time on the easy ones (30–60s) to spend on the hard ones. A useful checkpoint: you should be at roughly question 30 by the 60-minute mark.

Multiple-response questions

"Choose TWO" (or THREE) questions are graded all-or-nothing — partial credit doesn't exist. Treat each option as an independent true/false against the scenario, and make sure your picks are complementary, not two ways of doing the same thing. The question tells you exactly how many to select; selecting the wrong count is an automatic miss.

Keyword → service reflexes

When the priority word names what to optimise, these phrases name which service. Drill them until the mapping is instant — most questions hinge on exactly one of these.

The high-yield keyword reflexes. Cover the right column and recall from the trigger phrase.

Common traps to expect
  • Deep Archive when the SLA is minutes. Cheapest, but retrieval is hours — fails a "within minutes" requirement.
  • Multi-AZ vs Read Replica. Multi-AZ = availability/failover; Read Replica = read scaling. The question's priority word tells you which.
  • Security Group vs NACL. SG is stateful and allow-only; if the scenario needs an explicit deny or is "stateless" at the subnet, it's a NACL.
  • "Run your own X on EC2" when a managed X exists — almost always the distractor on a "least operational overhead" question.
  • Bigger instance for an AZ-failure requirement — a larger instance still dies with its AZ; spread across AZs.
  • Gateway vs Interface VPC endpoint. Gateway is free but only S3/DynamoDB; everything else is a paid Interface endpoint.

Interleaved final review

These six questions deliberately mix domains — storage, compute, database, networking, security, cost — in no fixed order. That interleaving is uncomfortable on purpose: it forces you to identify the topic before you can answer, which is exactly the skill the exam demands. Commit to an answer before revealing each explanation.

Q1. Which option does the method select?
Two microservices are tightly coupled: a spike in orders overwhelms the downstream fulfilment service and requests are lost. The team wants to decouple them and absorb traffic spikes with the least operational overhead.
Priority word: "decouple" + "absorb spikes" → SQS. A queue buffers messages so the consumer drains them at its own rate — durable spike absorption with zero servers to manage. (A) SNS is fan-out/push, not a buffer — a slow subscriber still gets overwhelmed. (B) self-managed broker is high operational overhead when a managed queue exists. (D) a bigger instance still has a finite ceiling and loses requests at the next spike. Answer: C.
Q2. Which option does the method select?
A read-heavy reporting dashboard runs on Amazon RDS (MySQL). The primary is fine for writes, but read queries are slow at peak. The team wants to scale read capacity with minimal effort.
Priority word: "scale read capacity" → Read Replicas. Replicas serve read traffic off the primary and you can add several. (B) is the classic trap: Multi-AZ is for availability/failover — the standby takes no read traffic. (C) snapshot-restore is stale and operationally heavy. (D) a full re-platform to a NoSQL store is a huge change for a relational reporting workload — wrong tool, massive effort. Answer: A.
Q3. Which option does the method select?
A real-time multiplayer game uses a UDP protocol and needs a static IP entry point plus near-instant failover across Regions. Which service best fits?
Priority words: "UDP" + "static IP" + fast cross-Region failover → Global Accelerator. It provides anycast static IPs, handles TCP and UDP, and shifts traffic between Regions in seconds. (A) CloudFront is for cacheable HTTP(S) content, not UDP game traffic. (B) ALB is HTTP/HTTPS only — no UDP. (C) Route 53 routing depends on DNS TTLs, so failover is far slower than Global Accelerator's. Answer: D.
Q4. Which option does the method select?
Security requires that a specific compromised IP range be explicitly denied at the subnet boundary for all instances in that subnet, regardless of their security groups.
Priority words: "explicitly denied" + "at the subnet boundary" → NACL. NACLs are stateless and support both allow and deny rules at the subnet level, covering every instance. (A) and (C) are wrong because security groups cannot express a deny — they are allow-only. (D) IAM controls API/identity permissions, not network packet filtering. Answer: B.
Q5. Which option does the method select?
A finance app must retain audit logs for 7 years. They're almost never read, but when an auditor asks, the firm must produce them within a few minutes — at the lowest possible storage cost.
Priority words: "lowest cost" but retrievable "within minutes" → Glacier Flexible Retrieval. Step 2 (eliminate non-functional) is the trap-breaker: (B) Deep Archive is cheapest but retrieves in hours, failing the minutes SLA. (C) S3 Standard meets the SLA but costs far more than needed for rarely-read data. (D) block storage is the wrong tool for long-term archival and isn't cheaper. (A) is cheap archival and meets minutes-level retrieval. Answer: A.
Q6. Which option does the method select?
A batch image-processing job is fault-tolerant (work can be retried) and runs for hours each night. The team wants the lowest compute cost for this flexible workload.
Priority word: "lowest cost" + "fault-tolerant" → Spot. Spot is the cheapest compute (up to ~90% off) and the interruption risk is acceptable precisely because the work is retryable. (B) Reserved Instances suit steady-state 24/7 usage, not a few hours a night — you'd pay for idle time. (A) and (D) are full-price On-Demand and don't exploit the fault tolerance that makes Spot safe here. Answer: C.

The one sentence to remember

Takeaway Read the priority word first, eliminate what doesn't work, let the matching pillar pick the winner, flag-and-return on anything that stalls you — and submit with zero blanks, because guessing is free.
