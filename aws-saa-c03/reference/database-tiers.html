Databases — Tiers & Properties

RDS, Aurora, DynamoDB, ElastiCache, and the purpose-built stores. Verified against AWS docs (Jun 2026).

The #1 database exam distinction Multi-AZ = high availability (synchronous standby, automatic failover, standby serves no traffic). Read Replicas = read scaling (asynchronous, can be cross-region, can be promoted). If the question says "offload reads" → Read Replica. If it says "survive an AZ failure / automatic failover" → Multi-AZ.

RDS

AspectDetail
EnginesMySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2
Multi-AZSynchronous standby in another AZ; automatic failover; not for read scaling
Read ReplicasAsync; read scaling; cross-region capable; promotable; up to 15 (engine-dependent)
BackupsAutomated: retention 0–35 days (default 7). Manual snapshots: kept until deleted, cross-region copyable
RDS ProxyConnection pooling; absorbs connection surges; faster failover; good for Lambda-heavy workloads
EncryptionKMS at rest (DB + logs + snapshots + replicas); enable at creation

Aurora

AspectDetail
Storage6 copies across 3 AZs, self-healing, auto-grows
ReplicasUp to 15 Aurora Replicas; failover to a replica typically <60 s (often <30 s)
Global Database1 primary + up to 10 secondary regions, replication lag typically <1 s — DR & global reads
Serverless v2Auto-scales compute fine-grained; for variable/unpredictable load
Exam tellMySQL/PostgreSQL-compatible + want best durability, fast failover, or global reach

DynamoDB (NoSQL key-value)

AspectDetail
LatencySingle-digit millisecond, massive scale
Capacity modesOn-demand (unpredictable/spiky, pay-per-request) vs Provisioned (predictable, cheaper, + auto-scaling)
DAXIn-memory cache → microsecond reads for read-heavy/repeat access
GSI vs LSIGSI = different partition key, added anytime (up to 20). LSI = same partition key, different sort key, at table creation only
StreamsItem-level change log, 24 h retention → triggers Lambda
Global TablesMulti-region active-active, last-writer-wins
TTLAuto-expire items by timestamp, no WCU cost

RCU/WCU: 1 RCU = 1 strongly-consistent read of 4 KB/s (or 2 eventually-consistent); 1 WCU = 1 write of 1 KB/s.

ElastiCache — Redis vs Memcached

FeatureRedisMemcached
PersistenceYes (snapshots/AOF)No (volatile)
Replication / Multi-AZ failoverYesNo
Data structuresRich (sorted sets, lists, pub/sub, streams)Simple key-value only
ThreadingSingle-threadedMulti-threaded
Exam tellDurability, failover, leaderboards, sessions, pub/subSimple, cheap, multi-threaded distributed cache

Caching strategies: Lazy loading (cache-aside; risk of stale) vs write-through (write cache+DB together; no stale, extra write latency).
